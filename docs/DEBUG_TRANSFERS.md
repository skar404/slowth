# Debug: записи, подключения и передача

В Debug доступны два транспорта: **Local HTTP без токена** и **S3 через HTTPS**. Они используют общую очередь и один формат снимка записи. Настройки → Debug → **Recordings** содержит скриншоты и эксперимент акселерометра; **Connections and transfer queue** — подключения и отправку.

## Локальный HTTP: быстрый старт

Из корня репозитория на Mac:

```sh
python3 -m venv /tmp/slowth-transfer-python
/tmp/slowth-transfer-python/bin/pip install -r scripts/requirements-debug-transfer.txt
/tmp/slowth-transfer-python/bin/python scripts/debug_transfer_receiver.py serve \
  --bind 0.0.0.0 --port 8765 \
  --advertise http://192.168.1.10:8765 \
  --root "$HOME/SlowthRecordings"
```

Заменить `192.168.1.10` адресом Mac в сети, доступной с телефона. `localhost` на iPhone указывает на сам iPhone. Mac и iPhone должны видеть друг друга по сети; при запросе iOS разрешить Local Network. Сервер по умолчанию слушает только `127.0.0.1`; `--bind 0.0.0.0` явно включает приём по LAN. Это локальный приёмник без авторизации, не публичный сервис.

Открыть `http://192.168.1.10:8765/` на Mac. Отсканировать QR стандартной камерой iPhone → открыть Slowth → **Save connection**. В приложении также можно вставить deeplink или вручную добавить URL. HTTP поддерживает частные IPv4, loopback, link-local, адреса Tailscale `100.64.0.0/10`, IPv6 ULA/link-local и `.local`; HTTPS допускается и для DNS-имён.

Приёмник не отправляет данные в labeler, не размечает и не объединяет датасет. Он сохраняет точные переданные файлы в `--root`.

## S3: QR с настройками

Сохранить конфигурацию в приватном JSON-файле вне репозитория. Пример структуры (значения заменить):

```json
{
  "version": 1,
  "profile": {
    "name": "Research S3",
    "transport": "s3",
    "endpoint": "https://s3.eu-central-003.backblazeb2.com",
    "region": "eu-central-003",
    "bucket": "your-private-bucket",
    "prefix": "recordings"
  },
  "credentials": {
    "accessKeyID": "YOUR_ACCESS_KEY_ID",
    "secretAccessKey": "YOUR_SECRET_ACCESS_KEY"
  }
}
```

Для временных AWS-ключей можно добавить строку `sessionToken` в `credentials`. У ключа должны быть права на PUT и HEAD/GetObject в выбранном префиксе. Используются S3 Signature V4 и path-style URL; virtual-host-only endpoints и multipart-загрузка в этой версии не поддерживаются. Предел одного файла — 5 GiB; отдельные кадры отправляются отдельными объектами.

```sh
/tmp/slowth-transfer-python/bin/python scripts/debug_transfer_receiver.py qr \
  --config /private/path/s3-connection.json \
  --output /private/path/slowth-s3-qr.html
```

Открыть HTML локально и отсканировать QR. Файл создаётся с правами `0600`, содержит ключи и не предназначен для публикации. Генератор не печатает ключи или ссылку в терминал. Слишком длинные настройки могут не поместиться в один QR; тогда использовать ручной ввод в приложении.

Ключи сохраняются только в Keychain этого устройства, доступны при разблокировке и не синхронизируются. Профили без секретов и очередь находятся в Application Support/DebugTransfers. Можно сохранить несколько подключений; импорт создаёт новый профиль и не перенаправляет уже поставленные в очередь записи. Отдельное удаление профиля доступно после удаления его незавершённых элементов очереди.

## Отправить запись

1. Скриншоты: включить **Save session screenshots**, выбрать интервал, запустить обычную запись экрана Slowth, остановить её, открыть **Screenshot sessions** и обновить список.
2. Акселерометр: записать эксперимент, загрузить данные через **Load recorded data**. Данные могут задерживаться до трёх минут; передаётся только уже загруженный снимок. Подробнее: [эксперимент акселерометра](MOTION_EXPERIMENT.md).
3. В выбранной записи указать **Destination**, нажать **Queue snapshot → …**.
4. Проверить назначение в очереди и нажать **Send pending**. Импорт QR и постановка в очередь сами ничего не отправляют.
5. Держать Slowth открытым. Переход приложения в фон приостанавливает передачу. После возвращения нажать **Send pending** либо **Retry** для ошибки. После перезапуска приложения очередь сохраняется.

Повтор сверяет файлы на сервере и не перезагружает уже подтверждённые. Ошибка/отмена не удаляет оригиналы. **Remove queued copy** удаляет запись из очереди и её неиспользуемую локальную staging-копию, но не исходную сессию и не удалённые объекты. Частично отправленные объекты на получателе сохраняются для повтора.

У каждого элемента фиксируются назначение и хеш снимка. Изменение меток, имени, числа кадров или догрузка акселерометра создаёт новый снимок. Отправка в HTTP не считается отправкой в S3. После завершения показывается подтверждение конкретного снимка, а не обещание, что продолжающаяся запись уже целиком отправлена.

## Скриншоты и совместимость

Новые screenshot sessions используют **PNG без потерь**, с исходными размерами буфера ReplayKit и метаданными ориентации. Это не обещание большего разрешения, чем предоставляет ReplayKit. Кадры не уменьшаются до размера входа ML-модели и не перекодируются при передаче.

PNG может занимать больше места и времени. Сохраняются прежние ограничения диска/длительности и ограниченная очередь кодирования; при перегрузке кадр пропускается, а счётчик `droppedFrames` увеличивается. Сбор скриншотов не задерживает callback распознавания. Отдельная старая функция **Save detection frames** для Photos не меняется.

У новых `session.json` `formatVersion = 2`; историческое поле `jpegBytes` оставлено как суммарный размер изображений для совместимости читателей. Старые JPEG-сессии отправляются как есть. Их нельзя превратить в исходные пиксели перекодированием. ZIP-экспорт поддерживает оба формата.

Существующий `slowth://labeler` и Keychain-токен labeler сохранены. Прямая старая отправка в labeler доступна для JPEG-сессий v1. PNG и акселерометр используют новый HTTP/S3-транспорт. Сервер в соседнем private dataset-проекте не менялся.

## Протокол v1

Deeplink: `slowth://debug-transfer#config=<base64url UTF-8 JSON без padding>`. JSON содержит `version`, `profile`, опционально `credentials`. Поле `profile.id` может отсутствовать в исходном JSON генератора: генератор добавляет UUID, а приложение при импорте всегда создаёт новый. HTTP-профиль содержит пустые `region`, `bucket`, `prefix`; `credentials` отсутствует. Параметры запроса, embedded URL credentials и неподдерживаемые версии отклоняются.

Общий инвентарь `COMPLETE.json`:

- `version: 1`, `kind: screenshots | motion`, `sessionID`;
- `files`: `name`, `size`, `sha256` (hex), `md5` (base64), `contentType`;
- `snapshotID` — SHA-256 точных байтов этого инвентаря. Он включён в путь, а не в сам документ.

S3 путь: `<prefix>/<kind>/<session UUID>/<snapshotID>/<file>`. Каждый PUT содержит `Content-MD5`, подписанный SHA-256 тела и `x-amz-meta-sha256`. После PUT выполняется HEAD с проверкой размера и SHA-256 metadata. Это **не независимая проверка скачанных байтов**; GET объектов не выполняется. `COMPLETE.json` записывается последним.

HTTP пути:

```text
HEAD/PUT /v1/recordings/<kind>/<session UUID>/<snapshotID>/files/<file>
HEAD/PUT /v1/recordings/<kind>/<session UUID>/<snapshotID>/complete
```

PUT передаёт сырые байты, `Content-Length`, `Content-MD5`, `X-Content-SHA256`; заголовка Authorization нет. Приёмник проверяет фактические байты, атомарно сохраняет файл и перед финальным маркером повторно проверяет весь инвентарь. Подтверждение завершения: `{"accepted":true,"snapshotID":"…"}`. HEAD возвращает размер и `X-Content-SHA256`. Совпадающий повтор допустим, другое содержимое по тому же пути получает 409. По умолчанию локальный сервер принимает файл до 512 MiB, инвентарь до 8 MiB. Перенаправления клиент не выполняет.

В motion-снимке: `samples.json` (Unix time, X/Y/Z в g с гравитацией), `motion.csv` и `session.json` (ISO-8601 даты сессии, метки с Unix time). Метки — действия пользователя, не предсказания модели. В screenshot-снимке остаётся исходный формат дат существующего `session.json` (Swift Date: секунды с 2001-01-01), PTS и ориентация кадров.

## Проверки

```sh
python3 -m unittest discover -s tests -p 'test_debug_transfer_receiver.py' -v
xcrun swift test --scratch-path /tmp/slowth-transfer-tests \
  --filter DebugTransferTests
xcodegen generate
```

Swift-проверки включают эталонную подпись AWS, повторы обоих транспортов, отмену, повреждённый снимок, реальную HTTP-передачу из Swift в Python. S3-транспорт проверяется на протокольных ответах; живой бакет требует отдельной проверки с выбранным пользователем профилем. Все инструменты приложения исключены из Release через `#if DEBUG`.
